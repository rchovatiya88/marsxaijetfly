## Freeze and score the actual candidate

Run the usual build/checks first, then:

```powershell
node scripts/bridgehead-acceptance.cjs freeze evidence/bridgehead-candidate-01
node scripts/bridgehead-acceptance.cjs verify evidence/bridgehead-candidate-01
node scripts/bridgehead-acceptance.cjs score evidence/bridgehead-candidate-01
```

`freeze` copies the production bytes into a new `build/`, creates a SHA-256 manifest plus source inventory, and writes an empty `acceptance.json`. Existing candidate directories are never overwritten. Serve that copied `build/` throughout scoring. Rebuilding the repository's `dist/` does not alter it. `verify` rejects changed candidate bytes; `score` verifies referenced evidence hashes and exits 2 for NOT YET, 1 for invalid files, and 0 only for PASS. A newly frozen candidate deliberately scores **0 recorded points, zero human sessions**. This measures completed evidence, not an assertion that every unobserved feature is broken.

Every evidence entry has a local `path` relative to `acceptance.json`, `sha256`, the frozen `candidateId`, and a descriptive `procedure`. Each engineering category has the exact complete-half checks and `evidenceRefs` plus review `notes`. Check booleans only when the named behavior is actually observed. Reusing a screenshot or a green unit test for unrelated criteria is invalid even if the schema can parse it. The tool validates the ledger's arithmetic and provenance; the reviewer still has to inspect evidence contents.

## Static terrain collision work completed in this iteration

The parent requested a bounded helper after the initial review. `src/triangle-collider.ts` now accepts baked `Float32Array` XYZ triangles and exposes `query(start, delta, radius)` for a continuous, double-sided swept sphere or zero-radius camera/weapon ray. It tests triangle faces, finite edge capsules and vertices; a static XZ grid, query stamps and reused candidate buffer avoid scanning the entire level per normal movement query. `move` projects remaining motion onto contact planes for slopes and corners. The constructor copies the source buffer, rejects nonfinite/malformed input, and ignores degenerate triangles. Build it while preparing the mission; retain the same collider throughout visual detail changes. The root agent integrated this helper with resident low chunks and shared world traces.

Seven focused tests cover boosted wall crossing from both sides, camera/weapon ray agreement, diagonal/tangent/outward movement, rounded edge and vertex contact, slopes, corners, broadphase deduplication, nearest hit/order/winding, and malformed geometry. Combined with the acceptance validator's eight tests, all 15 new helper/validator tests passed. At the combined integration checkpoint, all **69** repository tests and typecheck passed. This does not claim a browser rendering pass.

`node scripts/benchmark-triangle-collider.cjs` provides a repeatable actual-asset diagnostic. It decodes the four existing Draco low GLBs with the vendored decoder, bakes world transforms, builds the 172,065-triangle collider, installs the current seven authored boxes, and sweeps canonical high and low trajectories at radius 0.7 m. Every listed segment reached its target (maximum numerical error below 1e-15 m): high ascends to Y3.2 before the west detour and remains there to court entry; low stays at Y-0.8 across the bridge, climbs at X8 to Y0.6, and approaches the protected arrival at (11,0.4,-1.5). These are continuous geometry sweeps, not ordinary-input or human completions.

On this Windows x64 host using Node 24.13.0, one diagnostic built collision in about 819 ms. For 1,000 short queries after 200 warmup queries, median query cost was 0.0334 ms and p95 0.2836 ms, with at most 343 triangle candidates tested in any sampled query. These measurements exclude renderer, animation, browser scheduling, and UI. They do not establish the foreground frame-time gate or high-detail mesh equivalence.
